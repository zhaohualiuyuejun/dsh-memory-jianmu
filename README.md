# 建木 · jianmu

> 模块化记忆：存储 / 检索 / 处理 / 人格注入 / 认知，各层独立可装、可组合。

**建木**取自《山海经》的通天神树——向上生长、沟通天地。「建」是构建、组装，「木」是生长、扩展。五个插件像树的部位，各司其职，不互相抢活。

## 为什么做

现在的记忆插件大多**大而全**：存储、检索、整理、注入塞进一个包。结果是维护面大、权限过大、升级互相牵制，一处坏块可能拖垮全部。

建木把它们拆开：**每层只做一件事，层间只走一份显式契约**。每层都能单独安装使用，也能用元包一起装。

## 五层

| 层 | 插件 | 职责 | 权限边界 |
|---|---|---|---|
| 存储 | **根藏** · `dsh-memory-store` | 摄取会话原话、落盘、可重建 | 只读源；只写自己的库；不提供检索工具；不注入 |
| 检索 | **寻枝** · `dsh-semantic-recall` | 语义 + 字面召回原文，带回可下钻锚点 | 只读存储；不写；不注入 |
| 处理 | **熏习** · `dsh-memory-process` | 去重、标记取代、时效、归档/遗忘 | 读写自己的状态；不注入 |
| 人格注入 | **镜台** · `dsh-memory-persona` | 人格卡编辑、权限、可观测 | **唯一有权注入上下文** |
| 认知 | **年轮**（待定） | 从原话提炼事件/结论/关系 | 产生新内容；后置，不先立项 |

> 核心规则：**写只写自己的数据，读只读契约放行的数据，注入只有一层有资格。**

## 契约先行

层与层之间不互相调函数，只认一份数据契约：

- 文件布局、字段、`contractVersion` 版本号；
- 每条原话带锚点：`session` / `messageId` / `seq` / `role` / `t`；
- `chunks.jsonl` 是唯一真源，向量与索引都是可重建的派生物；
- 知识层（结论/摘要）必须带 `derivedFrom` 指回原话，不允许无来源的漂亮摘要。

契约文档：`docs/contract-v1.md`（待落地）。
