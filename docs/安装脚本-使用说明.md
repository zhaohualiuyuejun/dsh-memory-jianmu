# 安装脚本使用说明（`install-jianmu.mjs` / `安装建木.bat`）

> 适用：建木 五包 2026-11 公开发布版 · 更新 2026-11-14
> 位置：发布件根目录（与五个 tarball 同级）。双击 `安装建木.bat`，或在命令行跑 `node install-jianmu.mjs`。

---

## 0. 它做四件事（任一步失败 → 自动还原三文件）

1. **备份** profile 的 `package.json` / `pnpm-lock.yaml` / `cordis.patch.yml` → `backup-jianmu-install-<时间戳>/`（带 `SHA256SUMS.before`）
2. **装包**：先把五个 tarball 复制到 profile 的 `.jianmu-packages/` 自己保管，再优先用 DSH 自带 pnpm → PATH 上的 pnpm → npm（三种依次尝试）。这样以后清空下载目录、移动发布目录，已装的包与重装都不受影响。
3. **写 `bundles`**：往 profile 的 `dsh.profile.bundles` 追加包名（去重、保留原有顺序）
4. **核验**：`node_modules` 里有包、`bundles` 里有名字；不通过就还原

**它从不碰数据**：`~/.dsh/memory-jianmu` 与 `~/.dsh/session-recall` 一个字节都不动；也不删任何东西。

> **运行环境**：需要 Node.js **22+**。`安装建木.bat` 会依次找 DSH 安装目录、`~/.dsh/dsh-runtimes`、PATH 里的 node，所以没单独装 Node 的用户也能双击运行。
> 脚本找 pnpm 的顺序：`JIANMU_PNPM` → 与当前 node 同级的 DSH pnpm → `~/.dsh/dsh-runtimes/.../pnpm` → `%LOCALAPPDATA%\Programs\DeepSeek Harness\...\pnpm` → PATH 上的 pnpm / npm。

---

## 1. 常用命令

| 想做什么 | 命令 |
|---|---|
| 装到默认 `desktop` profile | `node install-jianmu.mjs`（或双击 `安装建木.bat`） |
| 装到指定 profile 名 | `node install-jianmu.mjs --profile desktop` |
| 装到任意目录 | `node install-jianmu.mjs --profile "D:\my-profile"` |
| 先看会做什么（不改文件） | `node install-jianmu.mjs --dry-run` |

> `DSH_HOME` 环境变量会被尊重：设了它就按 `<DSH_HOME>/profiles/<名字>` 找。

---

## 2. 装完要做什么

**重启 DSH 桌面版**（关掉窗口再打开）。侧栏会出现「根藏」「记忆库」「人格卡」等入口。

> 只是改了客户端代码的样式 → 页面 `Ctrl+R` 就够；**新增插件 bundle 必须重启**。

---

## 3. 卸载（脚本不代做，按下面手工来）

1. 从 profile 的 `package.json` → `dsh.profile.bundles` 里删掉名字（五包逐个装就删五个）；
2. **优先 `pnpm remove <五个包名>`**（实测干净：lockfile 同步、不留垃圾）；
   用 `npm uninstall` 也能卸掉包，但 **`pnpm-lock.yaml` 会留下陈旧条目**，之后 `pnpm install` 会报
   `ERR_PNPM_OUTDATED_LOCKFILE` 或 `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`（非交互窗口里必现）。
   已经用 npm 卸了的话，二选一：删掉 profile 的 `pnpm-lock.yaml` 再 `pnpm install`、或加 `--no-frozen-lockfile`；
   也可以**直接重跑一次 `install-jianmu.mjs`**（它会自愈 lock）。
3. 安装脚本复制到 profile 的 `.jianmu-packages/`（约 1.4MB）可留可删；删掉不影响已装好的包，但以后重装要先重新下载 tarball。
4. **数据不会被删**：`~/.dsh/memory-jianmu` 与 `~/.dsh/session-recall` 都留着，想清干净要手工删（先备份）。

> 忘了删 `bundles` 里的名字也不会炸：宿主启动时打印 `skipping profile bundle "…": cannot resolve …` 并跳过，其余照常。

---

## 4. 出问题怎么退回去

脚本每次都会备份。手动还原：

```powershell
$bk = "C:\Users\<你>\.dsh\profiles\desktop\backup-jianmu-install-<时间戳>"
Copy-Item "$bk\package.json","$bk\pnpm-lock.yaml","$bk\cordis.patch.yml" "C:\Users\<你>\.dsh\profiles\desktop" -Force
Get-FileHash "C:\Users\<你>\.dsh\profiles\desktop\package.json" -Algorithm SHA256   # 与 $bk\SHA256SUMS.before 对照
```

还原 `package.json` 后建议跑一次依赖安装（用 DSH 自带 pnpm），否则 `node_modules` 与清单可能对不上。

## 5. 实测记录（2026-11-13）

| 场景 | 结果 |
|---|---|
| 全新 profile + 默认模式 | 备份 2 文件 → 自带 pnpm 安装成功 → `bundles` 新增 5 行 → 核验通过 |
| 同一 profile 再跑一次（幂等） | `bundles：已存在，无需改动`，无重复项 |
| 脚本装出来的 profile 真启动 | 五个面 **5/5 探针 200**，日志无 `ERR_MODULE_NOT_FOUND` / `skipping` |
| 演练模式（`--dry-run`） | 只打印计划，profile 文件哈希不变 |
| 安装失败路径 | 三种安装器都失败时自动还原；实测曾因参数带空格失败一次，还原成功（脚本已修） |

**已知限制**：
- 脚本按文件名找五个 tarball，**必须在发布件根目录运行**（`安装建木.bat` 会自动切到自己的目录）。
- 公开版不含元包；元包仅内部实验用，`file:` 依赖是绝对路径，搬目录后失效。
- 只支持 Windows 上验证；macOS/Linux 未验证。
