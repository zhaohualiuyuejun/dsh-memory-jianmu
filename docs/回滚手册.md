# 回滚手册
> 适用：建木 五包 2026-11 发布准备 · 更新 2026-11-13

三条原则，先记住再看具体步骤：

1. **先备份，再动手。** 备份带时间戳，改完用 sha256 前后对照。
2. **只删自己刚建的、内容已知的路径；疑似自建的目录先移进 `.backup/`，绝不 `rm -rf`。**
3. **每一步都要有「怎么确认成功」**——不看命令返回什么，看产物本身。

| 出了什么事 | 看哪一节 |
|---|---|
| 要改 profile / 装包 / 卸包 | §1 三文件备份 |
| 要动数据（迁移、清理、修库） | §2 数据根备份 |
| 硬认领搬错了 | §3 硬认领回滚 |
| 设置改错了（含根藏 Key / 自动摄取） | §4 设置回滚 |
| 插件加载失败、工具消失 | §5.1 |
| 数据文件损坏 | §5.2 |
| 向量与块对不上 | §5.3 |

> 术语：**profile** ＝ DSH 配置档目录（`C:/Users/<you>\.dsh\profiles\desktop`）；**bundle** ＝ 插件包（写进 `dsh.profile.bundles` 才加载）；**journal** ＝ 回滚记录文件。
>
> **诚实标注**：§1（三文件备份/恢复）与「装 → 卸 → 重装 → 还原」已在**临时 profile** 实跑过一遍，记录在内部验收档案（未随公开版发布）；**生产 profile 上只做了备份 + 哈希对照，没有做过装卸**。§2 的数据根备份命令仍建议首次使用时先拿临时目录走一遍。

## 1. profile 三文件：备份与恢复

**目标文件**（三个一起备份，缺一不可）：

```
C:/Users/<you>\.dsh\profiles\desktop\package.json
C:/Users/<you>\.dsh\profiles\desktop\pnpm-lock.yaml
C:/Users/<you>\.dsh\profiles\desktop\cordis.patch.yml
```

**备份目录约定**：`path/to/jianmu\backup\release-rehearsal-<时间戳>\`

> 用《安装脚本》装的话，它会在**profile 目录里**自动建 `backup-jianmu-install-<时间戳>/`（同样三个文件 + `SHA256SUMS.before`），安装失败会自动还原；手工回滚时直接拿这份覆盖即可。

### 1.1 备份（并记录哈希）

```powershell
$ts   = Get-Date -Format "yyyyMMdd-HHmmss"
$prof = "C:/Users/<you>\.dsh\profiles\desktop"
$dst  = "path/to/jianmu\backup\release-rehearsal-$ts"
New-Item -ItemType Directory -Force $dst | Out-Null

foreach ($f in @("package.json","pnpm-lock.yaml","cordis.patch.yml")) {
  Copy-Item (Join-Path $prof $f) (Join-Path $dst $f) -Force
}

Get-FileHash (Join-Path $dst "package.json"),(Join-Path $dst "pnpm-lock.yaml"),(Join-Path $dst "cordis.patch.yml") -Algorithm SHA256 |
  Format-Table Hash,Path -AutoSize |
  Out-File (Join-Path $dst "sha256-before.txt")
```

**怎么确认成功**：

- 目录里确实有 3 个文件（`Get-ChildItem $dst`）；
- `sha256-before.txt` 里有 3 行哈希；
- 再对源文件算一次哈希，与备份逐个相等：

```powershell
Get-FileHash "$prof\package.json","$prof\pnpm-lock.yaml","$prof\cordis.patch.yml" -Algorithm SHA256 | Format-Table Hash,Path
```

### 1.2 恢复

```powershell
# 先把"现在这一份"也备份下来（否则回滚本身不可逆）
$now = "path/to/jianmu\backup\release-rehearsal-before-restore-$(Get-Date -Format 'yyyyMMdd-HHmmss')"
New-Item -ItemType Directory -Force $now | Out-Null
Copy-Item "$prof\package.json","$prof\pnpm-lock.yaml","$prof\cordis.patch.yml" $now -Force

# 再从备份恢复
Copy-Item "$dst\package.json","$dst\pnpm-lock.yaml","$dst\cordis.patch.yml" $prof -Force

# 对照哈希
Get-FileHash "$prof\package.json","$prof\pnpm-lock.yaml","$prof\cordis.patch.yml" -Algorithm SHA256 | Format-Table Hash,Path
```

恢复的是 `package.json` 时，还要让依赖树跟上（用**应用内置 pnpm**，不是系统 pnpm）：

```powershell
Remove-Item Env:CI -ErrorAction SilentlyContinue
node "<DSH_INSTALL>/resources/runtime/primary-runtime/dependencies/pnpm/bin/pnpm.cjs" install --no-frozen-lockfile --ignore-scripts
```

⚠️ **`pnpm install` 会重写 profile 的 `node_modules` 与 lockfile**。如果你在本机手动改过**第三方插件**的文件（打过补丁），装完要把那些补丁重新打一遍。**建木自身不需要任何补丁。**

**怎么确认成功**：

- 三个文件的 sha256 与 `sha256-before.txt` **逐个一致**；
- `pnpm install` 无 `ERR_MODULE_NOT_FOUND`；
- 重启 DSH 后五个工具面都在（见 §6 清单）；
- 第三方插件补丁（如有）已重打。

> ⚠️ 整文件恢复 `cordis.patch.yml` 会**连带回滚备份之后的其他设置改动**。如果只想回滚某一项（例如根藏的自动摄取开关），不要整文件覆盖——按 §4 就地改回那一个节点。

## 2. 数据根：备份与恢复

**数据根**：`C:/Users/<you>\.dsh\memory-jianmu`（根藏/熏习/年轮/镜台的数据都在这里，按人格分目录）。

### 2.1 备份

先看体积，别一上来就复制：

```powershell
$root = "C:/Users/<you>\.dsh\memory-jianmu"
Get-ChildItem $root -Directory | ForEach-Object {
  $s = (Get-ChildItem $_.FullName -Recurse -File -ErrorAction SilentlyContinue | Measure-Object Length -Sum).Sum
  "{0}`t{1:N1} MB" -f $_.Name, ($s/1MB)
}
```

再复制（保留目录结构）：

```powershell
$dst = "path/to/jianmu\backup\data-$(Get-Date -Format 'yyyyMMdd-HHmmss')"
robocopy $root $dst /E /R:1 /W:1 /NFL /NDL
# robocopy 退出码 0~7 都算成功；>=8 才是失败
```

**怎么确认成功**：

- 两边文件数一致：

```powershell
(Get-ChildItem $root -Recurse -File).Count
(Get-ChildItem $dst  -Recurse -File).Count
```

- 每个 `scopes/<人格>/chunks.jsonl` 的 sha256 两边一致（这是唯一真源，必须先对上）；
- 向量文件（`vectors_v1.f32`）体积一致——单个人格约 129MB 是正常量级。

### 2.2 恢复

1. 先报告用户，再停 DSH（**不擅自重启/关闭用户的程序**）；
2. 把当前数据根**改名**保留：`memory-jianmu.bak-<时间戳>`（不删）；
3. 把备份目录复制回 `C:/Users/<you>\.dsh\memory-jianmu`；
4. 核对文件数与 `chunks.jsonl` 哈希；
5. 启动 DSH，跑 `jianmu_store_status`。

**怎么确认成功**：状态里的总块数、人格数、未归属数与备份时一致；向量缺失/坏行为 0；无降级标记。

## 3. 硬认领回滚（`jianmu_persona_claim_hard`）

硬认领会同时动三层：根藏（`chunks` + 向量 + `identity`）、熏习（`state`）、年轮（`claims`）。所以它自带 journal，**回滚以 journal 为准**。

### 3.1 找到 journal

```
<dataRoot>\persona\hard-claim\<tag>\journal.json
```

journal 在 `persona/hard-claim/<tag>/` 下，记录了**三层各自的备份路径**与每个阶段的结果；各层备份实体在 `<dataRoot>/_archive/hard-claim-<tag>/`（根藏侧含 `root-journal.json` 与逐文件 sha256）。

### 3.2 执行回滚

```
jianmu_persona_claim_hard {
  to:             "<目标人格>",        // 必填，与认领时一致
  rollbackBackup: "<dataRoot>/persona/hard-claim/<tag>/journal.json",
  confirm:        true
}
```

> 传了 `rollbackBackup` 就**只回滚**，不会再搬一次。三层服务缺任一 → `SERVICE_UNAVAILABLE`，不会半搬。

### 3.3 怎么确认成功

| 核对项 | 期望 |
|---|---|
| 回滚返回 | 三层逐层结果均为成功；失败项要有明确报错，不能"看起来成功" |
| 根藏 | `jianmu_store_status`：两边块数恢复到认领前，**总块数守恒**；目标侧不再有 `provenance.hardClaimFrom` 标记的块 |
| 熏习 | `jianmu_process_status`：state 行数恢复；不再指向已搬走的块 |
| 年轮 | `jianmu_year_verify`：无**新增**孤儿锚点 |
| 身份 | `identity.json` 映射恢复到认领前；身份备份在 `<dataRoot>/_archive/`（`identity-*.json`） |

> ⚠️ 一处**不算失败**的预期：混合锚点的 claim 按 2026-11-13 拍板「不复制、不改写锚点」保留在源侧，被搬走的锚点会成为源侧孤儿（`ANCHOR_ORPHAN`）。预览里的 `orphanAfter` 就是这个数，**在预期范围内不算回滚失败**。

## 4. 设置回滚（0.2.6 起：设置写进 profile 的 `cordis.patch.yml`）

**写入路径（0.2.6 spike 结论）**：`ctx.settings.update(ns, patch, expectedRevision)` → 宿主设置服务 → 配置编辑器**就地**改 profile 的 `cordis.patch.yml`（`yaml.parseDocument` + `setIn`，注释与排版保留）→ 原子写。volatile 字段**热生效，不用重启**。

### 4.1 改错了怎么回

| 情形 | 做法 | 确认 |
|---|---|---|
| 只改错一个字段 | 在 UI 设置里再改一次（带 `expectedRevision`），或手工把 `cordis.patch.yml` 里该节点改回 | `GET /api/memory-store/settings` 读回一致；Key 只显示「已配置」布尔 |
| 整个文件被写脏 | 按 §1 从备份恢复该文件；**注意会连带回滚备份后的其他设置** | 文件 sha256 与备份一致；重启后设置仍在 |
| 保存报 `409 STALE_SETTINGS` | 说明 revision 过期：重新 `GET /settings` 拿新 revision，再保存 | 第二次保存成功且读回一致 |
| 宿主没有可写设置服务 | UI 降级为只显示，并提示手工改 `cordis.patch.yml`（**不会假装保存成功**） | UI 显示的是"只读/需手工改"，不是"已保存" |

**怎么确认设置真的生效**：

- 根藏：`jianmu_store_status` 的 `autoIngest` 字段（上次结果 / 下次时间）随开关变化；
- 看 `cordis.patch.yml` 里对应节点确实变了，且文件其余部分排版未被打乱；
- 重启一次再看——volatile 字段应当仍在（写盘成功的话）。

> 提醒：根藏的嵌入 Key 就落在这个明文 YAML 里；备份和分享前先遮挡。

## 5. 常见事故处理

### 5.1 插件加载失败 / 工具不出现

**先按顺序判断，别急着重装**：

1. **bundle 是不是启用的？** 常见坑：`installed=true, enabled=false` —— 这时重启多少次都不会加载，日志里也没有线索。用 `plugin_manager` 的 `set_bundle` 打开（`{ name, enabled: true }`），返回 `applied` 即热加载生效。
2. **是不是缺模块？** 报 `ERR_MODULE_NOT_FOUND` → 看该包版本是否已内置共享库（熏习 0.2.1 起已内置；根藏当前版本 0.2.8 同样随包内置）。
3. **profile 条目对不对？** `dsh.profile.bundles` 里必须有包名。

**处理**：

1. 从 `dsh.profile.bundles` 里**只移除出问题的那个名字**（保留其余条目）；
2. 用内置 pnpm 跑一次 `install --no-frozen-lockfile --ignore-scripts`；
3. 重启 DSH（先报告用户）；
4. 重新把名字加回、再 `install`、再重启。

**怎么确认成功**：工具面出现（例如根藏的 7 件、镜台的 19 件）；`plugin_manager list_plugins` 里状态正常；没有 `ERR_MODULE_NOT_FOUND`。

### 5.2 数据损坏（JSONL 坏行 / 向量尺寸不符）

1. **先把出问题的 scope 整目录快照**到 `<dataRoot>/_archive/manual-<时间戳>/`（不要在原目录上试修）；
2. 跑 `jianmu_store_rebuild`（某个人格）——**0 次嵌入、不扣费**，从 `chunks.jsonl` 重建索引；
3. 看结果提示。

**怎么确认成功**：

- `jianmu_store_status`：块数 = `chunks.jsonl` 行数；`index_meta.json` 指向当前向量文件；
- 向量缺失/坏行数下降为 0；
- ⚠️ 注意：`rebuild` **不会重嵌**。如果向量本身缺失或维度不对，它只恢复文本索引，并明确提示需要显式重嵌（v1 骨架没有一键重嵌入口）。需要重嵌时走文档里的脚本路径（会调用嵌入服务，先问用户）。

### 5.3 向量错位（块数与向量行数对不上）

1. 先关自动摄取：`autoIngest=false`（避免修的过程中又被写一次）；
2. 把该 scope 整目录快照到 `<dataRoot>/_archive/manual-<时间戳>/`；
3. 再 `jianmu_store_rebuild`；
4. **不要**手工裁剪 `vectors_v1.f32`——向量行序必须与 `chunks.jsonl` 严格一致，手工截断只会制造更隐蔽的错位。

**怎么确认成功**：

- `jianmu_store_status`（深检）里向量缺失/坏行为 0；
- 该人格的 `manifest.json` 的 `provider/model/dim` 与 `index_meta.json` 一致（换过嵌入模型时必须全量重建，不能只增量）；
- 检索能正常返回（寻枝侧跑一次简单查询）。

### 5.4 卸错了包 / 想装回来

1. 按 §1 备份三文件；
2. 重新装同名同版本包，把名字加回 `dsh.profile.bundles`；
3. `install` + 重启。

**怎么确认成功**：工具面恢复；**数据仍在**（数据根不在 `node_modules`，卸载不会删它）；`jianmu_store_status` 块数与卸载前一致。

### 5.5 卸完发现 profile 写脏了

按 §1 整文件恢复三文件 → `install` → 重启 → 安全网 repatch → 按 §6 清单验收。

## 6. 回滚后验收清单（逐项打勾）
