> 适用：建木 五包 2026-11 发布准备 · 更新 2026-11-13

本文回答：**只装一部分行不行、谁依赖谁、卸载后留下什么。**
⚠️ 先读口径：**全装、五个单装、两个关键组合都已实测（2026-11-13）**；单装只验证到"能启动 + 只读面可用"，不等于"业务全跑通"。

## 0. 状态口径

| 标记 | 含义 |
|---|---|
| 已验证 | 现场跑过，有产物/日志/工具面可核 |
| 待实测 | 计划中的组合，尚未逐项跑；发布前要补 |
| 未验证 | 完全没有证据 |

「全装」的依据是：发布集五包已装并加载（寻枝 0.4.7 / 根藏 0.2.8 / 熏习 0.2.7 / 年轮 0.4.5 / 镜台 0.3.8），临时 profile 启动后 5/5 面在线（2026-11-13 实测）；发布检查 `release-check` **54/54**（含干净安装后真注册硬认领工具）。

## 0.1 怎么装（推荐一键脚本）

发布件根目录的双击 `安装建木.bat`（或 `node install-jianmu.mjs`）：备份三文件 → 装包 → 写 `bundles` → 核验，失败自动还原；`--dry-run` 只看计划。详见《安装脚本-使用说明》。

## 1. 包名速查（profile 的 `dsh.profile.bundles` 里写的就是这一列）

先对几个反复出现的词：

| 看到的词 | 在这里指什么 |
|---|---|
| profile | DSH 的配置档目录：`C:/Users/<you>\.dsh\profiles\desktop` |
| bundle | 插件包；**只有写进 `dsh.profile.bundles` 才会被加载** |
| scope | 人格分区，数据在 `scopes/<人格>/` |
| claim | 从原话里提炼、带原话锚点的一条结论 |
| journal | 回滚用的记录文件（记着备份路径与每步结果） |

| 层 | 包名 | 当前版本 | 一句话 | 单独装能干什么 |
|---|---|---|---|---|
| 根藏 | `dsh-memory-store` | 0.2.8 | 原话存储层：只追加、可重建 | 自动摄取原话、状态卡、身份映射 |
| 熏习 | `dsh-memory-process` | 0.2.7 | 处理层：状态/重复/待处理/冲突候选 | 整理状态；没根藏时只剩「原话看板」 |
| 年轮 | `dsh-memory-yearring` | 0.4.5 | 认知层：带锚点的 claim | 从原话抽 claim、拼 topic 正文 |
| 镜台 | `dsh-memory-persona` | 0.3.7 | 人格层：人格卡与注入设置 | 建卡/版本/回滚/注入预览 |
| 寻枝 | `dsh-semantic-recall` | 0.4.7 | 会话语义检索 | 跨工作区召回原话；可完全独立 |
| 共享库 | `dsh-jianmu-utterance-core` | 0.1.0 | 抽取/切块共享库 | **不用单独装**：随根藏/熏习以内置依赖打包 |

> 共享库自 0.2.1（熏习）起改为 `bundledDependencies` 随包内置，干净安装不会再出现 `ERR_MODULE_NOT_FOUND`。

## 2. 单装（五包各一行）

| 场景 | 需要的 bundle 名 | 依赖 / 谁调用谁 | 安装耗时 | 卸载残留 | 状态 |
|---|---|---|---|---|---|
| 仅寻枝 | `dsh-semantic-recall` | **无 npm 依赖**、不 import 其他建木包；只读 `~/.dsh/sessions/`；可选读根藏数据根（`rootMode`）与 `identity.json`（软认领/源派生） | **0.49 s** | `$DSH_HOME/session-recall/`（索引 + `config.json`，含 Key）**不删**；删该目录才清干净 | **✅ 已实测**（启动 2.39 s；`state` 与 `workspaces` 两个探针 200） |
| 仅根藏 | `dsh-memory-store` | 内置共享库 0.1.0；对外提供宿主服务 `jianmuStore`（给镜台调）；自动摄取读写自己的数据根 | **0.56 s** | `~/.dsh/memory-jianmu/` 全部（`scopes/`、`identity.json`、`_logs/`）**不删** | **✅ 已实测**（启动 2.33 s；空库 `degraded=true` 因 `identity_missing`，属预期） |
| 仅熏习 | `dsh-memory-process` | 内置共享库 0.1.0；**只读**根藏数据根的 `scopes/<人格>/`，写 `process/<人格>/`；不读向量、不需要向量 | **0.57 s** | `~/.dsh/memory-jianmu/process/<人格>/`**不删** | **✅ 已实测**（启动 2.31 s；无根藏时 `capabilities`/`source/*` 全 200） |
| 仅年轮 | `dsh-memory-yearring` | 无 npm 依赖；**只读** `scopes/`（可选读熏习状态），写 `year/<人格>/`；不读向量 | **0.53 s** | `~/.dsh/memory-jianmu/year/<人格>/`（claims / topic_docs / runs）**不删** | **✅ 已实测**（启动 2.32 s；无根藏不崩） |
| 仅镜台 | `dsh-memory-persona` | 无 npm 依赖；可选调根藏 `jianmuStore`、寻枝 `jianmuRecall`、熏习 `jianmuConflicts`；**只写** `persona/` | **0.55 s** | `~/.dsh/memory-jianmu/persona/`（含 `_deleted/`、`hard-claim/` 记录）**不删** | **✅ 已实测**（启动 2.33 s；`installed=true / initialized=false`、cards 0） |

补充两条单装事实（来自各包 README，不是推测）：

- **熏习单装**：即使根藏和外部库都没有，只要 DSH 有 `<DSH_HOME>/sessions/`，仍会显示「原话看板」（只读扫会话、按人/天/工作区看原话）；状态/重复/待处理仍需 chunk 库。
- **镜台单装**：人格未在 `identity.json` 注册也能建卡，但会返回警告（无记忆 scope）；注入由镜台接管，不需要根藏在场。

## 4. 谁调用谁（缺了会怎样）

| 调用方 | 被调方 | 调用方式 | 被调方缺失时的行为 |
|---|---|---|---|
| 镜台 | 根藏 | 宿主服务 `ctx.get('jianmuStore')` | 一键登记 / 停记 / 硬认领不可用；硬认领要求三层齐全，缺任一返回 `SERVICE_UNAVAILABLE`（**不半搬**） |
| 镜台 | 寻枝 | 宿主服务 `jianmuRecall.prefetch` | P2 自动召回退化为「无服务」，不阻塞对话（且该功能默认关） |
| 镜台 | 熏习 | 宿主服务 `jianmuConflicts.list` | P2.5 冲突卡静默跳过（默认关） |
| 熏习 | 根藏数据根 | **文件只读**（`scopes/<人格>/manifest.json` + `chunks.jsonl` + 可选 `deleted.jsonl`） | 没有库 → 只剩「原话看板」；不报错 |
| 年轮 | 根藏数据根 | **文件只读**（同样只需 chunk 契约，不 import 根藏代码） | 没有库 → 无块可选，run 无事可做 |
| 寻枝 | 根藏数据根 | 只读 + 索引缓存（按 mtime+size） | 回退读自带索引（`$DSH_HOME/session-recall/`） |
| 根藏 | 寻枝配置文件 | 只读回退（`embeddingApiKey` 留空时读 `~/.dsh/session-recall/config.json`） | 没有 Key → 嵌入不可用、降级 |

**没有循环依赖**：根藏不 import 熏习/年轮/镜台；熏习与年轮互不 import（年轮只是可选读熏习状态）；寻枝不 import 建木任何包。这也是「可以只装一部分」的结构基础。

## 5. 元包（不在公开发布中）

公开发布**只提供五个包 + 一键安装脚本**。元包 `jianmu-all` 仅内部实验用：它的依赖是 `file:` 绝对路径，搬到别人的目录就会失效，所以不随 Release 发布。

装五包请直接用 `install-jianmu.mjs`（或双击 `安装建木.bat`），不依赖元包。

## 6. 卸载残留总账

**总原则：卸载插件不删数据。** UI 与插件都不删记忆；想清干净必须手工删目录，且先备份。

| 路径 | 谁写的 | 卸载后 | 想清干净怎么做 |
|---|---|---|---|
| `~/.dsh/memory-jianmu/` | 根藏 / 熏习 / 年轮 / 镜台 | **保留**（`scopes/`、`process/`、`year/`、`persona/`、`identity.json`、`_logs/`） | 先整目录备份，再手工删；不要 `rm -rf` 不明目录 |
| `$DSH_HOME/session-recall/` | 寻枝 | **保留**（索引 + `config.json`，**含 Key**） | 删整个目录即可清干净；原始对话在 `~/.dsh/sessions/` 不受影响 |
| profile `package.json` 的 dependencies | 安装器 | **卸载会删依赖项**（演练实测：sha256 变了）；`cordis.patch.yml` **不动** | 用 `remove_bundle`；失败则手工摘名字 + **`pnpm remove`**（先 `npm uninstall` 会让 lock 陈旧，之后 `pnpm install` 在非 TTY 下报英文错），或 `pnpm install --no-frozen-lockfile` |
| profile 的 `dsh.profile.bundles` | 安装器 | **`npm uninstall` 不会自动摘它**（演练实测） | 手工移除名字（保留其余条目）；**漏删不会炸**：宿主启动时打印 `skipping profile bundle "…": cannot resolve …` 并跳过，其余包照常加载 |
| `~/.dsh/sessions/` | 宿主 | **永远不动** | 建木只读，无需处理 |

> 卸载前请先做《回滚手册》§1 的三文件备份：卸载动作会改 profile 的三个文件。
