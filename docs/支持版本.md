> 适用：建木 五包 2026-11 公开发布 · 更新 2026-11-14

本文只写**有证据的支持范围**。没跑过的平台、没测过的组合，一律写「未验证」，不写成「兼容」。

## 2. 运行依赖

### 2.1 嵌入服务（寻枝、根藏共用口径）

| 项 | 要求 |
|---|---|
| 接口 | **OpenAI 兼容** `POST /v1/embeddings` |
| 本机实测模型 | `Qwen/Qwen3-Embedding-8B`，**4096 维** |
| 单块体积 | 4096 维 × 4 字节 = **16KB/块** |
| 可替换模型 | 例如 `bge-m3`（**1024 维**）——换模型必须**全量重建**，否则新旧向量混库 |
| 完全不出网 | 本机 Ollama（必须带 `--embeddings` 启动）或纯字面模式（`provider=none`） |
| 费用量级（实测参考） | 7 天语料全量约 0.2~0.5 元；之后增量几分钱（以平台当日标价为准） |

### 2.2 A2 摘要（根藏，默认关）

| 项 | 默认值 |
|---|---|
| 服务 | 本机 Ollama |
| 地址 | `http://127.0.0.1:11434` |
| 模型 | `qwen3:8b` |
| 触发 | 只给缺摘要的长块（默认 ≥80 字） |
| 缺失时 | Ollama 不可达直接跳过，不报错、不影响摄取 |

### 2.3 年轮的大模型

- 走**宿主模型路由**（默认 DeepSeek）；可用 `llmProvider` / `llmModel` 覆盖。
- 年轮自己不保存 Key。
- 每次抽 claim 都会产生 token 费用；每日有 `autoDigestDailyTokenBudget`（默认 120 万）安全阀。

### 2.4 客户端注入依赖（网页界面）

| 包 | 注入的客户端依赖 |
|---|---|
| 寻枝 | `@deepseek-ai/dsh-client-runtime`、`@deepseek-ai/dsh-client-ui-settings`、`@deepseek-ai/dsh-client-ui-settings-plugins` |
| 根藏 / 熏习 / 年轮 / 镜台 | `@deepseek-ai/dsh-client-ui-conversation`、`@deepseek-ai/dsh-client-ui-layout`、`@deepseek-ai/dsh-client-ui-sidebar` |

## 4. 已知兼容性注意

| 项 | 事实 | 影响 / 处理 |
|---|---|---|
| 会话格式 | 寻枝依赖 `session.v4.jsonl.zstd` | DSH 大版本换会话格式时要同步改 `lib/extract.mjs`，否则索引读不到 |
| DSH 0.2.1 及更早的致命缺陷 | 桌面版把工具库打进 `app.asar`；宿主工具取不到时插件会落到本地实现，**旧实现**没把裸参数表编译成 object 根，工具定义缺 `type` → 该会话所有请求失败 | 建木这批包的本地实现已编译 object 根（寻枝 0.2.2 起），0.2.1-rc.5 上不再触发；**仍建议升到 0.2.2**；急用时先关掉 bundle |
| 空库首次导入 | 只落文本块、**不产生向量**（`degraded:true`，`missingVectors` 报警） | 配好嵌入服务后等自动摄取重嵌或手动重嵌；`dim=0` 时语义检索不可用，属正常 |
| 设置写入（寻枝） | 寻枝 README 记录：本机 0.2.1-rc.5 上宿主设置写入「能读不能写」，所以寻枝**不依赖它**，写自己的 `~/.dsh/session-recall/config.json` | 寻枝的设置任何版本都能用；不要指望改宿主设置影响它 |
| 设置写入（根藏 0.2.6） | 走宿主设置服务，0.2.6 spike 已核实会**就地写入** profile 的 `cordis.patch.yml`（注释/排版保留、volatile 热生效） | 两者是**不同通道**，互不替代；根藏设置改错按《回滚手册》§4 回滚 |
| 共享库缺失 | 熏习 0.2.1 起把 `dsh-jianmu-utterance-core` 声明为内置依赖随包打包 | 干净安装不再报 `ERR_MODULE_NOT_FOUND`；更早版本会 |
| 寻枝索引天数 | 硬上限 365 天；保留窗口 = max(索引天数, 30) | 改小天数不会立刻删旧块，等窗口滑走 |
| 寻枝换嵌入模型 | 向量空间与维度不同（4096 vs 1024） | **必须全量重建**，只增量会得到混库 |
| 年轮每日 token 上限 | 内存计数，DSH 重启当天归零 | 它不是硬账本，不能当费用保险 |
| 元包激活 | 只装元包不激活（`--dump-config` 为 0 个条目）；加进 `dsh.profile.bundles` 后五层一次挂齐 | 必须把 `jianmu-all` 写进 bundles；挂齐已实测（根藏/熏习/年轮/镜台 4 个 HTTP 面 + 寻枝 `/state` 全 200，2026-11-13） |

### 0.2.2 兼容实测（2026-11-14）

在**隔离目录**（独立 `DSH_HOME`、随机端口、npm 版 `@deepseek-ai/dsh@0.2.2-rc.3`）做了一次真启动：

- `--dump-config`：五个 bundle 全部进组合树，**零兼容性警告**；
- 五个 HTTP 面全 **200**：`memory-store/healthz`、`memory-process/capabilities`、`year-ring/capabilities`、`persona/status`、`session-recall/state`；
- 客户端五个 `client.js` 都注入到根页面，合并 bundle 语法检查通过；
- 侧栏 **根藏 / 记忆库 / 人格卡 / 星图** 面板实际渲染；插件页五包均为「已启用」；
- 根藏首次导入（`jianmu_store_ingest`）在空库上写出 scope（4 块），`status` 能看到；
- `ingest-hourly.mjs --dry-run` 从真实 `session.v4.jsonl.zstd` 抽出 4 块，`SCOPE_MISSING` 不再出现在首次导入路径。

## 5. G2 / G3 / G4 文案口径（发布说明必须照这个写）

**只认实测数字，不写「显著增强」。** 下表每一条的数字来源见本节末尾。

> **基线口径（2026-11-13 补注，别误读）**：`73.7%` 这个起点**已经包含**「寻枝 A2 摘要索引 + bge 重排」；
> `+5.3pp` 全部来自**熏习 + 年轮**的跨层整理。**A2 不是本轮新增项**，也不是增益来源。
> 单看 A2 的离线收益是 H 67.3→70.7 / R 71.7→73.7；产品版 A2（根藏 `autoSummaryIndex`）与 bench 版本**同口径但不是同一份数据**，未单独重测 79% 那套。

| 指标 | 实测 | 口径 / 门槛 | 结论 |
|---|---|---|---|
| G2 联合检索 E@5 | 73.7% → **79.0%（+5.3pp）**，300 题 | 门槛 +5pp | 主体通过 |
| G2 foundP | **82.9%**（明细 82.94%） | 底线 83.0%（目标 85.0） | 差 0.06pp（约半题），**未过** |
| G2 multihop | 58% → **56%（−2.0pp）** | 任一题型跌幅 >−2pp 不允许 | 卡在边界，**未过** |
| G3 口径（跨层整理） | 联合卷 E@5 增益 **+5.3pp** | — | 只能写「跨层整理」 |
| G4 claim@5 | **53.3%** | ≥60% | **未过**（已知弱点） |
| G4 锚点有效性 | **100%** | 100% | 过 |
| G4 合计 | **3/5** | 全过 | 未过 |

### 可以这样写

- 「熏习 + 年轮跨层整理，在 300 题联合卷上把 E@5 从 73.7% 提到 79.0%（**+5.3pp**）。」
- 「命中精确率 **82.9%**，离 83% 底线差 0.06pp。」
- 「多跳题**不升反降 2 个百分点**（58% → 56%），这是已知限制。」
- 「claim@5 为 **53.3%**，仍是已知弱点（目标 60%）。」

### 不许这样写

- ❌「显著增强」「大幅提升」「全面超越」「彻底解决记忆问题」
- ❌ 把 +5.3pp 写成「翻倍」「数量级提升」
- ❌ 拿不同题库、不同口径的数字互相换算后对外宣传
- ❌ 只报通过项、隐去 multihop −2pp 与 claim@5 53.3%

> **数字来源：作者本机实测记录**——2026-11-10 熏习/年轮检索增益 S1/S2/S3 施工记录（未随公开集发布）。
> 这些都是本机单次/多次实测，不是基准测试；换嵌入服务或对话量，数字会变。

## 6. 未验证清单（发布说明里必须保留）

1. **macOS / Linux**：完全没有实测。
2. **Windows 10 / 11 的细分版本**：包内只声明「Windows」，未逐个小版本验证。
3. **Node 22 以上的具体版本**：只声明 `>=22`，未逐个主流大版本验证。
4. **无网页界面的宿主**（headless / tui 等）：只有寻枝 0.4.1 做了 Web 服务可选化，其余包未逐项实测。
5. **安装矩阵里除「全装」外的组合**：均为待实测（见《安装矩阵》§7）。
6. **元包 `jianmu-all` 的卸载残留**：挂载已实测通过（加进 bundles 后五层一次挂齐）；卸载后五个包是否残留、profile 条目是否自动摘除仍未实测。
7. **镜台像素级渲染**：侧栏入口与面板挂载已在 DSH 0.2.2-rc.3 隔离实例里确认（2026-11-14/15）；**像素级样式与各面板逐项内容**仍以实机为准。
8. **年轮星图 3D**：与本次发布解耦，不在支持范围内。
